# Controller hosting resolution

`resolveEnvironment(target, options)` reads provider deployment state. It does not deploy, promote, change IAM, create domains, or send provider credentials to workers. A saved connection is configured; a successful provider resolution confirms current control-plane readiness. Browser runs still need to reach and test the actual application.

- **URL:** an explicit HTTP(S) endpoint, including a reachable internal network address. No hosting account needed. Embedded credentials/query secrets are rejected.
- **Vercel:** saved Vercel OAuth or a manual token. The target project/team is explicit. Select a separate `branch` when the deployed baseline differs from the coding PR base. The latest matching preview must be READY; production deployments are excluded. An older success does not mask a new failed/building deployment.
- **Railway:** `RAILWAY_TOKEN`, or the target's `tokenSecret`. Account/workspace tokens use `tokenType: "account"` (the default); environment-scoped project tokens require `tokenType: "project"`. The resolver checks service/project/environment membership, token scope, the latest deployment's SUCCESS status, branch metadata when available, and public domain availability. Set `branch` for a distinct deployed baseline. Custom domains require valid DNS records and an issued certificate. No automatic authentication fallback is attempted.
- **Cloud Run:** `GCP_SERVICE_ACCOUNT_JSON`, or a target's `credentialsSecret`, containing a Google service-account JSON key. Without a saved/shared key, the controller uses Google's Application Default Credentials (for example `gcloud auth application-default login` or an attached Google Cloud service account). Explicit missing named credentials fail rather than falling back. Grant the identity Cloud Run Viewer or an equivalent role with `run.services.get` on the selected service/project; enable the Cloud Run Admin API. Cross-project service-account access is supported through IAM. Only official service-account key fields are accepted from dashboard JSON; executable, external-account and custom endpoint credentials are not imported through this form. ADC remains the operator-controlled auth library mechanism.

Cloud Run must finish reconciliation successfully at its current generation. The default HTTPS `run.app` URL must be enabled with public ingress and without IAP. The application must also permit browser access (for example an unauthenticated Cloud Run invoker); this resolver does not configure IAM or inject a Cloud Run identity token into the browser. Service-account credentials authenticate only controller API reads. Split traffic returns no single deployment ID, and Cloud Run resolution does not invent a commit SHA. These results do not establish that an unmerged coding candidate has been deployed or tested and cannot satisfy production promotion evidence.

Service-account JSON stored through Connections is validated, reduced to the needed fields, and saved in the local `.env` as compact JSON. Preserve this private file in configuration backups. POSIX permissions are 0600; Windows files receive the current user's ACL before credential contents are written. Never commit `.env`.

Provider requests reject redirects, cap response sizes, apply timeouts, and return sanitized errors without provider response bodies or credential values.

Primary contracts: [Railway authentication](https://docs.railway.com/integrations/api), [Railway services](https://docs.railway.com/integrations/api/manage-services), [Railway deployments](https://docs.railway.com/integrations/api/manage-deployments), [Railway domains](https://docs.railway.com/integrations/api/manage-domains), [Cloud Run service GET](https://docs.cloud.google.com/run/docs/reference/rest/v2/projects.locations.services/get), [Cloud Run readiness fields](https://docs.cloud.google.com/run/docs/reference/rest/v2/projects.locations.services), [Google Auth Library credential validation](https://github.com/googleapis/google-auth-library-nodejs).
