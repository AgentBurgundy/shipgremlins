# 100 ways to improve ShipGremlins

Audited October 14, 2026. This is a code-backed improvement review and implementation record for easier setup, autonomous project work, local Docker and hosted staging, self-healing tickets, and a simpler dashboard.

**100 improvements implemented; all 11 previously listed backlog items are complete in this working tree.** Three implementation agents worked on environment setup, execution recovery, and dashboard design. The primary agent integrated autonomous startup, project controls, scheduling isolation, readiness continuation, documentation, and end-to-end checks. Pre-existing working-tree changes were preserved. The entries below describe this pass; enabled-by-default PMs and prior staging work were already present and are not claimed as new work.

The working flow is now: connect a repository and Claude Code, adopt an enabled PM, automatically queue initial repository Discovery, create and browser-verify one local worker when necessary, prepare missing ticket mappings and normal connection checks when their prerequisites recover, then run scheduled patrols and pick up approved tickets. Project home explains current work and gives one Enable/Pause control. Existing paused crews stay paused.

Automatic coding requires approved tickets with acceptance criteria. Owners may explicitly enable bounded low-risk approval; its durable audit and exact diff limits remain authoritative. Compose import supports a documented isolated subset, missed patrols catch up once, and staging/production review boundaries remain in force.

Implemented means the change exists with source/automated-test evidence in this working tree. It does not mean every live provider combination has been certified. Browser QA exercised the real dashboard and enable/pause HTTP handlers with disposable synthetic provider/worker data at desktop and 390px mobile sizes. Live Docker builds, OAuth, and hosted staging deployments were not exercised against customer projects.

The completed follow-up evidence is recorded in `docs/audits/backlog-environments.md`, `backlog-recovery.md`, `backlog-dashboard.md`, and `backlog-autonomy.md`. Older provider runs without authenticated workflow-input evidence still require manual inspection.

Final verification: **157 test files passed; 2,495 tests passed and 6 skipped.** TypeScript, ESLint, diff whitespace checks, and real packaged CLI installation/staged-update smoke tests passed. Desktop and 390×844 browser QA verified the overview, project state, and Enable/Pause controls. Preview screenshots are in `.run/improvements-qa/`. Docker Desktop was launched for a disposable runtime check, but its Linux engine did not become available; no live-container success is claimed. Hosted-provider authentication and staging deployment still require live certification.
