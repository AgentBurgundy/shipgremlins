# Ticket recovery and autonomous execution improvements

Audit date: 2026-10-14. Scope: dispatcher recovery and the durable local worker engine. These 25 opportunities are numbered 026–050 for the consolidated 100-item audit. All 25 are now implemented with regression coverage. Items 049 and 050 were completed in the follow-up backlog implementation; detailed proof is in [backlog-recovery.md](backlog-recovery.md).

Recovery can retry a confirmed pre-execution failure or reconcile an existing completion record. An uncertain provider request must be investigated before starting more agent work. These changes do not merge, deploy, publish a second PR, or change a ticket's workflow state.

## Validation

- Final dispatcher and local-runner regression suite passed: 21 files, 408 tests passed and one skipped. This includes bootstrap, lost response/receipt, restart, owner-handoff, and mid-read approval revocation cases.
- TypeScript checking and linting of the changed dispatcher and engine files passed.
- Tests use injected forge, Linear, Docker, clocks, storage, and failure timing. They establish controller behavior and restart safety; they do not establish that Docker is installed, account credentials work, or a live staging application is reachable on this machine.

## Remaining limits

Provider request ambiguity remains visible until authenticated association or acknowledgment can establish the existing work. Older workflow revisions that did not record exact inputs require manual provider inspection; their scope is never guessed. These changes preserve the local engine's refusal to automatically repeat agent/publication work after a confirmed execution failure. Cross-process remote dispatcher claims still depend on the deployment's dispatcher concurrency controls because Linear's label API is not a compare-and-set claim.
