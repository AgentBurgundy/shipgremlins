# ShipGremlins v0.29.0

PMs and coding agents are now separate, named agents.

- PMs own investigations, proposals, prioritization and QA. Their controls only
  manage product management work. PM activation no longer enables coding.
- Coding agents have their own names, provider/model dropdowns, automatic pickup,
  manual runs, concurrency and assigned PM ticket queues. The project and global
  Agents pages show these profiles separately from workers.
- Existing coding settings migrate to named coder profiles without changing their
  enabled state or effective model. New projects start without coders, and adopting
  another PM does not silently create one.
- Project-wide pause preserves each agent's individual setting. Queued runs retain
  coder identity across restart. Deleted or replaced profiles cannot inherit old
  runs, and duplicate tickets cannot be admitted through another coder.
- Staging repairs also retain their coder identity and model route. Existing
  approval, finite-scope, WIP, QA and production-completion protections remain in
  effect. Missing provider credentials never trigger a provider fallback.

Install from **Settings → Updates**, then restart the controller. Open a project's
**Agents** page to review migrated coders or create new ones. Named coding agents
run through the local controller with local or remote Docker workers; the legacy
CI workflow cannot execute saved coder identities or model choices.

See [PMs and coding agents](../CODING_AGENTS.md) for setup and migration details.
