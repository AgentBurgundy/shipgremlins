# ShipGremlins v0.26.0

Use Codex with your ChatGPT account when Claude Code is unavailable. Open
**Connections → AI provider**, select **Codex**, and choose **Sign in to Codex**.
Finish the official device-code sign-in yourself. You can also import an existing
managed ChatGPT `auth.json`. Docker's Linux engine must be available on the controller.

- One workspace choice controls new setup analysis, PM planning, discovery,
  patrols, coding, and repair jobs on controller-managed local or enrolled workers.
  Existing runs retain their provider. A disconnected or exhausted provider blocks
  new work with an actionable message; there is no billing/provider fallback.
- The trusted controller serializes account refresh and keeps refresh credentials
  away from model-capable workers. Canceled or replaced sign-ins cannot overwrite
  a newer account. Account imports, logs, artifacts, learned context and public
  build arguments use the same private credential boundaries.
- Codex uses the existing app/browser tools and implementation checks. Discovery
  has bounded read-only repository tools; setup planners receive only inert context
  and structured output. Repository configuration cannot add Codex capabilities.
- Advanced settings accept a model override, with a provider default when empty.
  Switching providers resets the override. Claude behavior remains supported.
- Codex usage separates fresh input from cached input and records output once.
  Unknown cache-creation counts remain unknown, so reports are partial rather than
  fabricated complete totals. Device sign-in does not count as a model turn.

The connection screen has keyboard-accessible provider choices, masked private
imports, sign-in progress/cancellation, and responsive desktop/phone layouts.
See [setup instructions](../SETUP.md#choose-your-ai-provider).

Existing standalone GitHub Actions installations retain their Claude settings.
Live customer sign-in and a real model turn were not exercised: verification used
synthetic credentials, real CLI protocol/configuration checks, local provider
fixtures, and browser interactions. Docker Desktop's Linux daemon was unavailable
on the verification machine. This release does not change the coder into a staged
multi-agent implementation process; the existing CLI agent loop and delivery gates
remain in place.

Install through **Settings → Updates** or `gremlins update`. The staged updater
preserves configuration, credentials and retained work.

Release validation: 3,846 tests across 224 files passed (6 skipped), plus 18 native
integration checks. TypeScript, lint, formatting, dashboard bundle consistency,
project/cron validation, packaged global installation, and staged update/rollback
checks passed. The package explicitly verifies that all Codex runtime and UI files
are included.
