# ShipGremlins v0.27.0

See what your crew is doing without opening each run. Overview and Activity now
show active-run stage rails, provider, elapsed time, repair counts and expandable
timelines. Stale workers keep their last observed stage; older runs without stage
records say so.

Ordinary coding runs now use an enforced implementation process: plan against
acceptance criteria, check the baseline, prove failing behavior tests when needed,
implement, obtain a fresh read-only review, and pass final configured checks before
publishing. Repairs share a two-attempt budget. Source-bound evidence prevents
publishing a candidate that changed after review. Staging sync and promotion repair
paths retain their established semantics.

Keep Claude Code and Codex connected together. Choose a project default and separate
PM/coding defaults in **Project → Settings → AI choices**. Override an individual
PM and its coding work in **Product brief → AI choices**. Choices inherit clearly,
offer model dropdowns, and never fall back to another provider silently.
Active runs keep their recorded provider; queued work resolves its route at launch.

Model dropdowns load the pinned providers' catalogs without starting a model turn.
They include Provider default, preserve previous saved choices if a catalog is
unavailable, and label supported lists honestly. Catalog presence does not certify
account access.

See [the coding process](../CODING_WORKFLOW.md) and
[provider setup](../SETUP.md#choose-your-ai-provider).

The workflow records checkpoints and evidence; it does not resume edited source
across replacement containers. Existing standalone CI workflows keep their provider
configuration. Verification uses synthetic credentials and model responses; live
customer sign-in and a paid model run are not certified by those tests.

Install through **Settings → Updates** or `gremlins update`. The staged updater
preserves configuration, credentials and retained work.

Local release validation: 3,990 tests across 233 files passed (7 skipped), plus
18 native integration checks. TypeScript, lint, formatting, dashboard bundle
consistency, project/cron validation, packaged global installation and staged
update/rollback passed. Desktop/mobile browser checks cover live stage cards and
workspace/project/PM model selection. Pinned Claude and Codex catalog/reviewer
protocols were exercised without a model turn or real account credentials.
