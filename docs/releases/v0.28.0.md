# ShipGremlins v0.28.0

ShipGremlins now has a dark mission control interface: graphite surfaces, cyan
actions, compact typography and consistent controls across every dashboard page.
Navigation separates daily work from workspace configuration. Active run cards
keep the current stage and process map visible; expand a card for its recorded
history. Errors and stale observations stay visible.

Connecting an existing app takes two screens after choosing that path: select its
repository, then review its editable project name. Source accounts, GitLab server
validation and unfinished setup drafts are preserved. Connections starts with AI
and source control; optional services remain searchable across all categories.

Project setup presents one next action and an expandable readiness checklist.
Use either a managed Docker environment or your hosted staging app, with guided
test-account setup when needed. Advanced environment controls stay available in a
disclosure. Repository-only projects skip browser setup after connecting Linear.
First-run guidance checks the project's chosen AI account instead of assuming the
workspace default is the account it will use.

**Start autopilot** uses the existing single revision-guarded crew activation:
every PM and coder must pass readiness before their flags are saved together.
It preserves the saved approval and delivery policy. Activation results remain
visible if the following refresh fails, and a failed run is no longer presented
as merely scheduled work.

Project and PM pages emphasize current outcomes, blockers and actions. Usage
emphasizes the total, trend and project comparison; report gaps remain visible,
with detailed token definitions and diagnostics available on demand.

Install through **Settings → Updates** or `gremlins update`.

See [setup](../SETUP.md) and the
[design and verification audit](../MISSION_CONTROL_DESIGN_AUDIT.md).

Local release validation passed: 4,016 tests across 234 files (7 skipped), 18
native integration checks, TypeScript, ESLint, formatting, dashboard bundle
consistency, project/cron validation, packaged installation and staged
update/rollback. Browser checks use real dashboard APIs and persisted disposable
configuration with simulated external services. This host's Linux Docker daemon
is unavailable; live worker execution and paid model calls remain unverified.
